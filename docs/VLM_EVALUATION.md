# VLM解释改进的本地对照

目标是提高判断和解释的实际可用性，而不只是改善措辞。默认继续使用本地`srdp-qwen3-vl-2b`；不训练、不下载新模型，不改检测器阈值。真实图片、参考答案、实际请求和输出都留在Git忽略的`work/`或本机材料目录。

## 复用检测结果，只重跑解释

在本地创建一个不提交Git的清单，例如`work/vlm-cases.local.json`：

```json
[
  {
    "name": "case-1",
    "bundle": "D:/SRDP/work/analysis-runs/<已完成任务>/bundle.json",
    "reference": { "note": "仅供人工核对，不进入模型" }
  }
]
```

```bat
run.cmd run vlm:evaluate -- --cases work/vlm-cases.local.json
```

可选`--model <本地标签>`、`--host <地址>`。默认host是本地Ollama，不使用在线图片检索。命令复制任务快照、保留原始检测结果，真实调用解释服务，输出至`work/vlm-evaluations/<runId>/`：

- `results.json`：结果、耗时、请求数、结论来源和人工参考信息。
- `*-explanation.json`：实际解释报告及原始模型返回。
- `*-requests.json`：实际请求，含图片base64，仅本地保存。

原证据包不修改。已有explanation报告与清单reference不进入新一轮输入。模型失败/模板回退会明确记录，并使命令返回非零退出码；不把回退算作解释成功。

明确且签名/文件绑定检查通过的AI来源声明走来源事实汇总路径，`decisionSource=evidence_fusion`、`aiGenerationSource=credentials`；可能有零次模型请求，这代表直接引用检测与来源记录，不计作VLM推理成功或提示词改进。该路径与普通VLM路径分别评价。

筛查与定位相互支持的输入可走`linked-evidence-summary`路径：VLM只识别位置内容和推测手法，检测事实由记录汇总。它与自由正文生成分别统计；`evidenceLinks`可用于检查是否误把不同任务当分歧。既有掩码真值仅用于事后定位评价，不能进入模型或决定某个样例走哪条路径。

## 对照时固定什么

固定图像、检测输出、来源报告、模型和资源预算。旧来源报告可能仍有已经修复的水印误报，因此应先更新来源报告，再让两个方案共享同一份快照。增加模型请求数、换模型或改变证据时单独标注，不能直接归因为提示词优化。

VLM不接收图名中的数据集类别、用户指定的修改位置、原始未修改对照或真值掩码。它们只用于人工评价。

## 分别评价什么

1. 判断：AI生成、局部编辑和正常图像能否正确区分，是否将任务差异误称为冲突。
2. 目标：是否对应实际位置、对象或字段；不能把票据订单号写成原价。
3. 证据：是否使用来源记录，是否将整图结果错误赋给某个区域。
4. 图像关系：原图、裁剪是同一图像，不能虚构编辑前后差异或不存在的原始文本。
5. 手法：单独核对正确性，不能把合理措辞等同正确；模型推测保持来源标识。
6. 可用性：结论和正文一致、首段清楚、无重复和截断，耗时与真实进度可接受。

文档字段对应另测来源OCR框与RiSE区域的几何关联：同一行或重叠文字可以作为“该区域附近实际读到的原文”，但程序只报告空间关系，不把文字自动命名为订单号、原价或水印。没有几何关联时才让VLM查看整图与原始局部进行记录/字段对应。

结构/引用测试只证明工程传递正常，不替代以上内容评价。开发样例至少包含正常对照；在独立材料上评价前不声称客户级准确率或泛化能力。

## 2026-11-07观察

五例开发对照覆盖短信、CASIA水鸟、带AI来源凭证图片、正常照片和票据。多种直接融合、先选证据、中文字段和任务拆分方案仍出现虚构依据、任务混淆和原图/裁剪误比较，尚未证明整体优于现有流程，因此未将这些实验直接替换APP默认链路。

确认并修复的工程问题：SICA判断输入补上已有的阈值距离支持度，临界分类不再只按接近0.5的类别分数表述为中等支持；未选重点区域时不再生成“位置被定位”的重复首段。原分数、分类阈值和数值置信度定义不变。

水鸟样例在本地CASIA清单中对应`Tp_D_...ani10198_ani10197_12407.jpg`，包含不同源图ID，本地评测归类为splicing；此前将它当作copy-move正确例的口头假设不能用于验收。真值分类和文件名不进入模型。
